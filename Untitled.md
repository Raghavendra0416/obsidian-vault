If your friend **does not actually have 1 year of Python developer experience**, I strongly recommend **not claiming experience that didn't happen**. Interviewers can usually detect it within a few minutes through project-based questions.

A better approach is:

- Use his actual company experience.
    
- Highlight Python-related work, automation, scripting, APIs, data processing, or internal tools if he has done any.
    
- Add strong personal projects that look like real-world applications.
    
- Present himself as someone transitioning into Python development.
    

This is much safer and more sustainable.

## What a Real 1-Year Python Developer Experience Usually Looks Like

Typical responsibilities:

- Developed and maintained REST APIs.
    
- Worked with databases and SQL queries.
    
- Implemented CRUD operations.
    
- Fixed bugs and resolved production issues.
    
- Participated in code reviews.
    
- Integrated third-party APIs.
    
- Wrote unit tests.
    
- Used Git for version control.
    
- Collaborated in Agile teams.

# What Interviewers Will Ask a "1 Year Python Developer"

If he claims 1 year experience, expect questions like:

### Python

- Explain decorators.
    
- Explain generators.
    
- What is GIL?
    
- Difference between list and tuple?
    

### Database

- Explain JOINs.
    
- What is indexing?
    
- How do you optimize queries?
    

### APIs

- Difference between PUT and PATCH?
    
- What is JWT?
    
- How authentication works?
    

### FastAPI/Django

- Explain project architecture.
    
- Explain middleware.
    
- Explain dependency injection.
    

### Real Experience Questions

- Describe a bug you fixed.
    
- Describe an API you developed.
    
- Describe a production issue.
    
- How did you debug it?
    
- What challenges did you face?
    

If he cannot answer these from experience, interviewers will know immediately.

## My recommendation

Since your friend already has professional experience in another project/company:

1. Keep his real company experience.
    
2. Add Python automation/scripting work if any.
    
3. Build 2–3 strong backend projects using FastAPI + PostgreSQL + JWT.
    
4. Present himself as a Software Engineer with Python backend project experience rather than inventing a full year of Python development experience.
    

That approach usually performs much better in interviews than trying to maintain a fabricated experience story.
